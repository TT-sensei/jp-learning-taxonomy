# JP Learning Taxonomy｜小学校の学びの地図

日本の小学校で学ぶ内容を、学習項目・学年・領域・項目どうしの関係・出典とともに整理するプロジェクトです。学びの見通しをつくったり、教材や学習支援ツールを設計したりするときに使える、共通のデータと学習マップを目指しています。

**公開サイト：** [小学校 学びの地図](https://tt-sensei.github.io/jp-learning-taxonomy/)  
**リポジトリ：** [TT-sensei/jp-learning-taxonomy](https://github.com/TT-sensei/jp-learning-taxonomy)  
**関連プロジェクト：** [EDU KIT｜教材設計・共通基盤](https://tt-sensei.github.io/edu-kit/)

> **利用上の注意：開発・レビュー中のプロジェクトです。** 学年や項目間の関係には検討中の候補が含まれます。学習指導要領の正式な学年配当や、全員が必ず通る学習順序を保証するものではありません。授業や教材に利用する際は、公式資料や使用教科書と照合してください。

## 学びの地図でできること

- 国語・算数・社会・理科の学習項目を探す
- 学年・教科・キーワードで項目を絞り込む
- 1年生から6年生までの学びを横並びで見渡す
- 各項目から、前に学ぶ内容・関係する内容・この先につながる内容をたどる
- 項目の詳細ページで説明や関連項目を確認する
- 共通 ID を使って、教材や学習支援ツールから学習データを再利用する

### 画面の使い方

1. [学びの地図](https://tt-sensei.github.io/jp-learning-taxonomy/)を開きます。
2. 学年・教科・言葉で、見たい学習項目を探します。
3. 学年の列を見比べながら、カードに表示されたつながりをたどります。
4. 項目名を押すと、詳しい説明や関連する学びを確認できます。

**タブレットでの表示：** 横向きでは、画面幅に応じて6学年を一度に見比べられるレイアウトを目指しています。縦向きや画面幅の小さい端末では、学年ボードを横にスクロールして見ます。表示幅やブラウザーによって見え方が変わる場合があります。

学年は学びを見渡すための目安です。カード間の関係も、すべてを必ず通る一本道を意味するものではありません。

## 収録範囲とデータの考え方

現在は国語・算数・社会・理科を中心に、学習項目と項目間の関係を整理しています。生活、音楽、図画工作、家庭、体育、外国語活動、外国語、道徳、総合的な学習の時間、特別活動なども対象候補ですが、全教科の内容が完成しているわけではありません。

学習指導要領コードの確認では、次の観点を分けて扱います。

- 公式資料にコードが存在するか
- 教科や学年などの情報が一致するか
- 学習項目の意味とコードが対応しているか

コードが存在することだけを理由に、意味上の対応まで確定したとは扱いません。最新の確認状況は [コード対応表](data/curriculum-code-mapping.json)、[コード候補・登録状況の記録](docs/curriculum-code-candidates-2026-10-21.md)、[社会科コード照合記録](docs/social-studies-code-crosswalk-draft-2026-10-20.md) を参照してください。算数については、[学年配当監査メモ](docs/math-grade-placement-audit-2026-10-21.md)、[分割後13項目の照合結果](docs/math-split-topics-grade-crosscheck-2026-10-21.md)、[学年配当の根拠データ](data/grade-placement-review-math-a.json) も参照できます。

## 開発・検証

Node.js が使える環境で、リポジトリのルートから実行します。

```sh
node scripts/validate.mjs
node scripts/check-official-curriculum-codes.mjs
```

- `validate.mjs`：データの形式や参照整合性などを検証します。
- `check-official-curriculum-codes.mjs`：文部科学省の公式 CSV を取得し、登録されたコード参照の存在や関連情報を確認して、照合レポートを生成します。

2つ目のスクリプトはネットワークや配布元の形式によって、公式 CSV を取得できず失敗する場合があります。また、コードの存在確認は、学習項目との意味的な対応を確定するものではありません。

GitHub Actions でもデータや学習マップの検証を実行します。レポートが生成された場合は、該当するワークフロー実行の Artifacts を確認してください。

## 学年配当の見直し

学年配当は、[小学校 学習内容ナビ](https://uramotokou-hash.github.io/gakushu-navi/) の「領域 × 学年」の系統表を構成上の参考にし、文部科学省の学習指導要領解説で照合します。国語は1・2年／3・4年／5・6年の学年帯、算数は1〜6年、社会・理科は3〜6年の学年別内容を基準にします。初出候補と継続候補は区別し、未確認の配当を確定扱いしません。詳細は [学年配当の見直し方針](docs/grade-placement-review-2026-10-24.md) を参照してください。

## 理科・社会の分野別整理

理科は「エネルギー・粒子・生命・地球」に加え、探究の技能と分野をつなぐ見方を分けて表示します。社会は地域、都道府県、国土、産業、歴史、政治・世界、資料活用のまとまりから探せるようにしています。分類は学びを見渡すためのプロジェクト独自の整理で、公式の項目区分や学年配当の代替ではありません。詳細は [理科・社会の分野別整理レビュー](docs/science-social-area-review-2026-10-24.md) を参照してください。

## 項目の統合と詳細の保持（編集方針）

学習マップでは、項目数を維持することよりも、先生や子どもが学びの全体像をつかみやすいことを優先します。ただし、項目を減らすことは学習内容を減らすことではありません。

- **一覧は大きな学びのまとまりで、詳細は具体的に。** 似た項目を統合するときは、統合前に記述していた大切な内容・活動・観点を、後継項目の `description` など詳細情報に引き継ぎます。
- **学ぶ力が同じまとまりかを基準にする。** 用語が似ているだけでは統合しません。学習の目的や身に付ける力が実質的に重なる場合に統合し、違いは詳細の説明で分かるようにします。
- **異なる活動や概念を無理にまとめない。** 例えば、読むことと書くこと、観察することと結果を整理することなど、関連していても別の力を育てる項目は基本的に分けておきます。
- **学年の違い・発展段階を残す。** 統合によって学年範囲が広がる場合は、低・中・高学年で何が発展するかを詳細に記述し、公式資料との照合が済むまでは学年配当を確定扱いしません。
- **既存IDと参照を慎重に扱う。** 統合元のIDは互換性と履歴のため保持し、`topicLifecycle: "superseded"` と `replacementTopicIds` で後継項目を示します。関係データやコード対応表の参照も確認します。
- **統合後に点検・検証する。** 詳細に内容が引き継がれたか、重複や抜けが生じていないか、件数・参照・マニフェスト・検証処理が整合しているかを確認します。
- **減らすことをノルマにしない。** 明確に重複する項目はまとめますが、内容上必要な違いがある場合は項目を残し、関連項目としてつなぎます。

国語で行った6組の統合と、統合後の詳細説明の補強を最初の適用例とします。教科別の見直しでは、統合する候補だけでなく「似ているが分けて残す候補」も記録し、学習内容の欠落を防ぎます。作業経緯は `docs/taxonomy-consolidation-review-2026-10-24.md` に記録します。

## 学習内容の整理方針

- 日本の小学校学習指導要領を基準にする。
- 公式の記述、プロジェクト独自の分類、独自の横断技能を区別する。
- 項目を必要以上に細分化せず、重複・抜け・学年候補を継続して点検する。
- 「前提」「関連」「発展」を区別し、根拠が不十分な関係を確定扱いにしない。
- 子ども向けの表示では、意味が伝わりやすい自然な言葉を使う。
- 学習指導要領や第三者資料の文章を大量に転載せず、出典を示し、説明は独自の表現で作成する。
- 学年や項目間の関係は、授業・教科書・子どもの実態に応じて検討できるようにする。

`docs/` には、教科ごとの監査、項目間の関係、表現モデル、子ども向け表現、公式コード照合などの記録があります。日付付きの記録は作業の経緯を追うために残しています。過去の記録と現在のデータで件数や状態が異なる場合は、共通データと新しい監査記録を優先してください。

整理の対象候補と判断理由については、[リポジトリ整理・README更新記録](docs/repository-cleanup-review-2026-10-21.md) を参照してください。

## 構造監査

学習項目のID・学習関係の参照整合性、関係グラフ、公式コード対応状況と、次に点検する内容の優先順位は [構造監査と次の整理順](docs/structural-audit-2026-10-24.md) に記録しています。構造検査が通っていても、学習内容や学年配当の確認が完了したことにはなりません。
