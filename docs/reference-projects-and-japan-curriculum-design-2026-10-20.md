# 参考プロジェクト比較と日本の学習指導要領に基づく再設計方針（2026-10-20）

## 結論

既存データを捨てて他国・他社の分類を移植するのではなく、データ構造と見せ方のよい点だけを参考にし、日本の小学校学習指導要領を内容整理の基準として組み直す。現在の274項目は完成した全教科カタログではなく、算数・国語・社会・理科の試作データとして扱う。

## 参考にしたプロジェクト

### 1. Marble Skill Taxonomy
- URL: https://github.com/withmarbleapp/os-taxonomy
- 参考にする点：学習項目を小さく定義する、項目ごとに説明と到達を確かめる観点を持たせる、関係に強さと理由を持たせる、出典となるカリキュラムと対応づける、JSON Schemaと検証スクリプトで整合性を確かめる。
- 日本向けに変える点：英米の標準や学年帯をそのまま使わず、日本の教科・学年・内容構成を基準にする。項目名や説明文、依存関係の理由はコピーせず、独自に記述する。
- 注意：同プロジェクトのデータと文章には個別のライセンス条件がある。構造の学習とデータの複製は分けて考える。

### 2. 人教版小学数学知识图谱
- URL: https://github.com/Xww-coder/pep-primary-math-taxonomy
- 参考にする点：学年・上下巻などの単位で内容の抜けを点検する、知識点・関係・まとまり・基準との対応を分ける、検索や領域絞り込みで項目の前後をたどれるようにする。
- 日本向けに変える点：中国の教科書配列・項目・コードを取り込まない。日本では教科書会社ごとに単元配列が異なるため、特定社の配列を全国共通の正解とせず、学習指導要領を基準にし、教科書は補助的な照合資料として使う。
- 注意：教材に由来する内容は転載せず、複数資料を照合して独自に整理する。

### 3. Learning Trajectories / LT²
- URL: https://www.learningtrajectories.org/lt-resources/learning-trajectories
- 参考にする点：学習目標だけでなく、子どもの考え方の発達と活動をつなげて考える。
- 日本向けに変える点：学習段階を一律の発達順序と断定せず、授業・教材設計に役立つ見方として扱う。

### 4. OpenPatch Learningmap
- URL: https://github.com/openpatch/learningmap
- 参考にする点：学習経路を作る・共有する・探索するという操作設計。
- 日本向けに変える点：まずデータの正確さと、児童・教師が迷わずたどれる画面を優先する。外部サービスやバックエンドへの依存は増やさない。

## 日本版の基準資料

第一の基準は文部科学省の「小学校学習指導要領（平成29年告示）」本文・解説とする。教科ごとの解説資料は文部科学省の公式一覧を起点に確認する。

- 文部科学省「小学校学習指導要領解説」：https://www.mext.go.jp/a_menu/shotou/new-cs/1387014.htm
- 文部科学省「平成29・30・31年改訂学習指導要領（本文、解説）」：https://www.mext.go.jp/a_menu/shotou/new-cs/1384661.htm
- 文部科学省「小学校学習指導要領コード」関連資料：https://www.mext.go.jp/a_menu/other/data_00001.htm

公式資料の内容区分・学年段階と、プロジェクト独自の学習項目・学習経路は別レイヤーで管理する。コードは実際のコード表と照合できたものだけ登録する。学習指導要領の文章や図表は大量転載せず、出典を記録して独自の要約を書く。

## 採用するデータ設計

1. **教科等 → 公式の内容構成 → 学習項目 → 学習上のつながり** の順にたどれるようにする。公式の領域名と、検索・表示のための独自クラスターを混同しない。
2. 学習項目は「一つの学びとして説明・確認できる大きさ」を目安にする。大きすぎる項目は分割候補、小さすぎる重複項目は統合候補とし、項目名だけで機械的に判断しない。
3. 各項目は、可能な範囲で「何を学ぶか」「子ども向けの表現」「対象学年・学年帯」「公式内容との対応」「出典」「確認状況」を持つ。未確認の学年や対応は未確認と明示する。
4. 関係は少なくとも「前提として必要」「先に学ぶと役立つ」「関連する」「発展・活用につながる」を区別する。必修の順序だと確認できない関係を、必ず通る一本道として表示しない。
5. 到達を確かめる観点（例：説明できる、表現できる、手順を使える）は、授業で使える独自の短文として追加する。公式の評価規準と誤認される表示は避け、未レビューの項目には付与しない。
6. 教科ごとに内容構成が違うことを尊重する。全教科を算数のような計算系統に押し込まず、国語の言語活動、社会の見方・資料活用、理科の問題解決、図工の表現過程など、それぞれの性質に合わせる。
7. 項目IDは維持し、名称・領域・学年候補の修正で参照を壊さない。削除・統合時は移行表と全参照の検証を先に行う。
8. JSONの参照整合性、重複、必須フィールド、学年・教科の妥当性を検証する。データ検証と、内容が日本の学習指導要領に正確に対応しているかの専門的レビューは別の検査として記録する。

## 現在のデータに対する判断

- 現在の274項目（旧項目を含む）・178関係は、全教科の網羅版ではない。現在の中心は算数で、国語・社会・理科は初期草案である。
- 公式コード対応表は枠があるが、個々の項目の照合が終わっていない。コードを推測で埋めない。
- 国語の学年帯、社会・理科の一部のまとめ項目、算数の学年候補と関係は、引き続き確認対象。
- 今後は単に項目数や矢印を増やすのではなく、公式内容構成との対応、重複・抜け、関係の根拠、児童にとっての分かりやすさを優先する。

## 次の作業順

1. 公式の内容構成と現在の項目を教科別に照合し、未対応・対応先が曖昧・重複候補を一覧化する。
2. まず既存の4教科を点検し、項目の追加より先に分類の粒度と抜けを整理する。
3. 学習項目と関係のデータ検証を自動化し、壊れた参照や二重登録を公開前に検出する。
4. 内容が確認できた範囲から、児童向けマップを「教科 → 大きなまとまり → 今の学び → 前に学んだこと／この先につながること」の順に使いやすくする。
5. その後、残りの教科等へ広げる。教科数だけを増やして、内容が未確認の項目を完成済みに見せない。

## 参考リンクの扱い

上記の外部プロジェクトは、構造・設計・探索体験の参考として記録した。データ、文章、図版、独自の学習項目は移植しない。日本の内容は文部科学省の資料を主な基準にし、出版社資料は補助的な照合に使う。
