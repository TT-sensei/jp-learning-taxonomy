## フィールドの意味

- `candidateCode`：意味的な対応が未確定の候補コード。候補が複数ある場合は `candidateCodes` に保持する。
- `verifiedCode` / `verifiedCodes`：公式コード表の本文・教科・学年を照合し、学習項目と対応することを確認したコード。複数コードが対応する場合は配列を使う。
- `relatedParentCodes`：関連する公式の親内容区分。参照・階層探索用であり、直接対応を示すコードとして扱わない。
- `relatedOfficialCodes`：独自の細分化・横断項目に関連する公式の具体的な記述。関連をたどるための参照であり、直接対応コードではない。
- `officialAudit`：確認した版・日付・コードの存在・教科／学年の整合性・意味対応の判定などの監査メモ。
- `matchStatus: "verified"`：直接対応を確認して登録した状態。ただしプロジェクト独自の項目構造そのものが公式の独立単元であることは意味しない。
- `matchStatus: "candidate"`：公式の関連コードは存在するが、草案側の独自分割・内容の幅・一対一対応が未確定であるため継続確認する状態。
- `matchStatus: "no-direct-match"`：横断技能や独自のまとめ項目など、一つの公式コードを直接割り当てないほうが適切な状態。関連コードがあっても、候補／確定コードとは分けて保持する。

## 現行の公式資料

- 文部科学省「文部科学省 教育データ標準」：https://www.mext.go.jp/a_menu/other/data_00001.htm
- 学習指導要領コード表（全体版）：https://www.mext.go.jp/a_menu/other/data_00002.htm
- 82V12公式CSV：https://www.mext.go.jp/content/20230901-mxt_syoto01-000010374_27.csv
- 82V12公式Excel：https://www.mext.go.jp/content/20230901-mxt_syoto01-000010374_28.xlsx
- 学習指導要領LOD（探索用の補助）：https://jp-cos.github.io/Dataset

LOD由来の最初の候補は82V11を参照して作成した。現行掲載の82V12とは版が異なるため、公式82V12のCSV本文を基準に照合し直す。候補コードを機械的に確定コードへ昇格させることはしない。

## 自動検証

- `scripts/validate.mjs`：topic ID、コード形式、状態の整合性、未登録参照などを検証する。
- `scripts/check-official-curriculum-codes.mjs`：候補・確認済み・関連コードを82V12公式CSVに照合し、項目名と下位コードを含むレポートを生成する。
- GitHub Actions の `Validate learning data` ワークフローで両方を実行し、詳細レポートを `official-code-audit-report` アーティファクトとして保存する。

機械検査はコードの存在、教科、学年を支援するもので、意味的な判断に代わるものではない。各教科の学習項目説明と公式本文の整合性は継続して確認する。
