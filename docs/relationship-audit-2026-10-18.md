# 学習項目間の関係：監査ログ

更新日：2026-10-18

## 今回の確認範囲

- `data/dependencies.json` の関係ID、項目ペア、関係タイプ、理由文
- `data/topics.json` の学年候補との整合性（前提・推奨前提のみ）
- `scripts/validate.mjs` の学年配当ステータス検査

この監査は関係の重複や構造的な矛盾を見つける初回チェックです。170件すべての教育的妥当性を確認済みとするものではありません。

## 修正した点

同じ「元項目 → 先項目」のペアが別の関係タイプで重複していた4件を整理しました。

| 対象 | 対応 | 理由 |
|---|---|---|
| 除法の意味 → あまりのある除法 | `grade-link-115` を削除 | 既存の `math-edge-011` と同じペア。より強い「前提」の登録を残し、重複表示を防ぐ |
| 小数の加法・減法 → 小数の乗法・除法 | `grade-link-118` を削除 | 既存の `math-edge-021` と同じペア。推奨前提の関係を残す |
| 平均 → データの特徴を多面的に捉える | `math-edge-040` を削除 | 同じペアに「推奨前提」と「関連する学び」が併存していたため、必須に近く見えない「関連する学び」を残す |
| 小数の位取りと大小 → 0.1 と 1/10 の関係 | `proposed-math-edge-a-002` を削除 | 既存の `math-edge-052` と同じペア。関係タイプの重複を解消 |

結果として関係候補は174件から170件になりました。同一ペアの重複は0件です。現時点の「前提」「先に学ぶと役立つ」関係について、候補初出学年の順序が逆転しているものは検出されていません。ただし、学年自体が確認中の候補であるため、これを教育的妥当性の証明とは扱いません。

## 検証スクリプトの修正

学年配当データには `candidate`、`needs-review`、`reviewed` の各ステータスが実際に使われています。検証スクリプトが `needs-review` を未定義として扱っていたため、実データのステータスを許容するよう修正しました。また、根拠情報の値を一つの固定文字列に限定せず、`basis` が記録されているかを検査するようにしました。

## 継続して精査すること

1. **関係タイプの強さ**：「前提」と「推奨前提」は、先の学習に本当に必要かを確認する。「関連する学び」は、順序を示す矢印として誤読されないか確認する。
2. **学年の整合性**：候補初出学年だけでなく、継続学年・単元の扱い・教科書の系統を照合する。学年候補が逆転して見える関係は、誤りと即断せず根拠を確認する。
3. **関係の方向**：理由文を読んで、矢印の向きが説明と一致しているか確認する。
4. **項目の粒度**：公式の内容項目とプロジェクト独自の細分化を区別し、異なる粒度の項目を無理に直線的につながない。
5. **出典と根拠**：関係ごとに根拠となる公式解説・教材資料を確認し、編集上の推論と資料で確認できた内容を分ける。
6. **未整理を可視化**：根拠が足りない関係を追加してつながっているように見せず、確認中のまま残す。

すべての関係は引き続き編集上の候補です。公式の必修順序や学習のロック条件として扱いません。
